# DentalDX — เว็บแอปวิเคราะห์ข้อมูล Data Exchange สภาวะทันตสุขภาพ

[![Build Windows EXE](https://github.com/nchotenin-tech/DataExchange-Analytics/actions/workflows/build-windows.yml/badge.svg)](https://github.com/nchotenin-tech/DataExchange-Analytics/actions/workflows/build-windows.yml)

วิเคราะห์ข้อมูลตรวจฟันจาก HDC แยกตามกลุ่มอายุ พร้อม drill-down จังหวัด → อำเภอ → หน่วยบริการ
ทำงานในเครื่องผู้ใช้ทั้งหมด **ไม่ส่งข้อมูลออกนอกเครื่อง และไม่ต้องต่ออินเทอร์เน็ต**

## ⬇ ดาวน์โหลด (สำหรับผู้ใช้ทั่วไป)

ไปที่ **[Releases](https://github.com/nchotenin-tech/DataExchange-Analytics/releases/latest)**
→ โหลด `DentalDX-vX.Y.Z-win64.zip` → แตกไฟล์ → วางข้อมูลใน `data/` → ดับเบิลคลิก `DentalDX.exe`

ไม่ต้องติดตั้ง Python ไม่ต้องติดตั้งอะไรเพิ่ม

> Windows อาจเตือน *"Windows protected your PC"* เพราะไฟล์ยังไม่ได้เซ็นใบรับรองดิจิทัล
> กด **More info → Run anyway**

## สำหรับผู้ใช้งาน

### 1. วางไฟล์ข้อมูล

```
DentalDX/
├─ DentalDX.exe
├─ data/
│   ├─ 6-12y/    ← วางไฟล์ .xlsx ของเด็ก 6-12 ปี ที่นี่ (วางกี่ไฟล์ก็ได้)
│   └─ 0-5y/     ← วางไฟล์ .xlsx ของเด็ก 0-5 ปี ที่นี่
├─ reference/    hospitals.csv, dentalfile.csv
├─ profiles/     ไฟล์เงื่อนไขการคำนวณของแต่ละกลุ่มอายุ
└─ cache/        โปรแกรมสร้างเอง (ลบได้ ไม่มีผล)
```

### การใช้งานหน้าจอ

- แถบภาพรวมเปรียบเทียบ **รายอำเภอ** เรียงตามรหัสอำเภอ แสดงกราฟแท่งคู่:
  ร้อยละได้รับการตรวจฟัน (เขียว) กับ ร้อยละปราศจากฟันผุ (ม่วง)
- **คลิกที่แถวอำเภอในตาราง** เพื่อไล่ลงดูรายหน่วยบริการในอำเภอนั้น
- หรือเลือกจากเมนูซ้าย: จังหวัด → อำเภอ → หน่วยบริการ

### สรุปประเด็น (Insight) อัตโนมัติ

ทุกตารางมีกล่อง **💡 สรุปประเด็นสำคัญ** (แสดงอยู่แล้ว กดปุ่มที่หัวตารางเพื่อซ่อน) แบ่ง 2 ส่วน:

**ภาพรวมของตาราง** — คำนวณจากตัวเลขในตารางนั้นตรง ๆ:

- ค่าภาพรวมของตัวชี้วัดหลัก
- แนวโน้มจากอายุน้อย → อายุมาก และบอกว่าดีขึ้นหรือแย่ลง
- อายุที่ควรเน้น (ค่าด้อยที่สุด) เทียบกับอายุที่ดีที่สุด
- ช่วงอายุที่เปลี่ยนแปลงเร็วที่สุด = จุดที่ควรแทรกแซงก่อน
- เตือนเมื่อฐานข้อมูลน้อยกว่า 30 คน (ตีความยาก)

**แยกรายอายุ** — การ์ดละ 1 อายุ เทียบกับค่าภาพรวม พร้อมชี้ตัวชี้วัดที่เป็นปัญหาเด่นของอายุนั้น
สีการ์ด: เขียว = ดีกว่าภาพรวม, แดง = แย่กว่าภาพรวม, เหลือง = ระวัง (ฐานน้อย)

> ทั้งหมดเป็นกฎคำนวณในเครื่อง ไม่ต้องต่ออินเทอร์เน็ต และทุกข้อความอ้างอิงตัวเลขจริงในตาราง
> เกณฑ์ที่ถือว่า "ต่างอย่างมีนัย" คือ 2 จุด/ซี่ (แก้ได้ที่ `MIN_GAP` ใน `core/insight.py`)
> ไฟล์ Excel แบบ "ส่งออกทุกตาราง" มีชีต **สรุปประเด็น** รวมทุกข้อไว้ให้ด้วย

### ดูกราฟของแต่ละตาราง

ตารางสถิติ (สภาวะฟัน / ปริทันต์ / ความจำเป็นต้องรักษา) มีปุ่ม **📊 ดูกราฟ** ที่หัวตาราง
กดแล้วจะแสดงกราฟแท่งเทียบทุกตัวชี้วัดแยกตามอายุ กดซ้ำเพื่อซ่อน

- ตารางร้อยละ → แกน Y คงที่ 0-100%
- ตารางค่าเฉลี่ย → แกน Y ปรับอัตโนมัติตามข้อมูล
- ตารางที่ 1 (คุณภาพข้อมูล) ไม่มีปุ่มกราฟ เพราะเป็นตารางตรวจสอบ ไม่ใช่ตัวชี้วัด

### ส่งออกรายงาน

- ทุกตาราง (รวมตารางภาพรวมรายพื้นที่) มีปุ่ม **⬇ CSV** และ **⬇ Excel** ที่หัวตาราง
- ปุ่ม **⬇ ส่งออกทุกตาราง (Excel)** มุมขวาบน = ไฟล์เดียว แยกเป็นชีต
  (`ข้อมูลรายงาน`, `ภาพรวมรายพื้นที่`, `ตารางที่ 1` … ) พร้อมเงื่อนไขการคำนวณกำกับบนหัวชีต
- ไฟล์ที่ส่งออก **ยึดตามขอบเขตที่เลือกอยู่** (จังหวัด/อำเภอ/หน่วยบริการ) ชื่อไฟล์บอกขอบเขตให้
- Excel ทำหัวตาราง 2 ชั้น (เช่น ปราศจากฟันผุ → จำนวน / ร้อยละ) และเน้นแถว "รวม" ให้อัตโนมัติ

### ติดตามเด็ก (คอลัมน์ "ติดตาม" ขวาสุดของตาราง)

มี 2 ปุ่มต่อแถว ทั้งระดับอำเภอและระดับหน่วยบริการ:

| ปุ่ม | หมายถึง | ใช้ทำอะไร |
|---|---|---|
| **ยังไม่ได้ตรวจ (n)** | ไม่มี `date_serv` ในข้อมูล | นัดมาตรวจ |
| **ไม่ผ่านเกณฑ์ (n)** | ตรวจแล้วแต่ตกเกณฑ์คุณภาพ จึงไม่ถูกนับในตารางที่ 2 เป็นต้นไป | ตามมาตรวจ/บันทึกใหม่ |

รายชื่อ "ยังไม่ได้ตรวจ" มี PID, ชื่อ, วันเกิด, อายุปัจจุบัน, บ้านเลขที่, ตำบล, typearea

รายชื่อ "ไม่ผ่านเกณฑ์" เพิ่ม **สาเหตุที่ไม่ผ่านเกณฑ์** (ระบุว่าตกข้อไหน เช่น
`PTEETH > 0` หรือ `provider_type in (02,06) + PTEETH > 0`) พร้อมวันที่ตรวจ ผู้ตรวจ
และจำนวนฟันที่บันทึกไว้ — ดูออกทันทีว่าเป็นปัญหาการตรวจหรือการบันทึกข้อมูล

- ช่องค้นหาด้านบนกรองได้ทุกคอลัมน์ (ชื่อ / PID / บ้านเลขที่ / ตำบล)
- ปุ่ม **⬇ CSV** และ **⬇ Excel** ส่งออก **ครบทุกรายการ** (หน้าจอแสดงสูงสุด 1,000 แถวเพื่อความเร็ว)
- ปุ่มบนหัวตารางส่งออกได้ทั้งอำเภอในไฟล์เดียว
- ไฟล์ Excel บังคับคอลัมน์รหัสเป็น "ข้อความ" แล้ว เลข 0 นำหน้าจึงไม่หาย
  (ถ้าเปิด CSV ด้วย Excel เลข 0 นำหน้าอาจหาย — แนะนำให้ใช้ปุ่ม Excel)

## เพิ่มกลุ่มอายุใหม่ (ไม่ต้อง build exe ใหม่)

1. คัดลอก `profiles/_TEMPLATE.yaml.txt` → เปลี่ยนชื่อเป็น `profiles/ชื่อกลุ่ม.yaml`
2. แก้ `id`, `label`, `age_range`, `quality_filter` และรายการ `tables`
3. สร้างโฟลเดอร์ `data/<data_folder>/` แล้ววางไฟล์ข้อมูล
4. เปิดโปรแกรม — กลุ่มใหม่จะขึ้นในเมนูเอง

**แก้เงื่อนไขการคำนวณของกลุ่มที่มีอยู่** ก็แก้ที่ไฟล์ `profiles/*.yaml` ได้ตรง ๆ
ไม่ต้องแตะโค้ดและไม่ต้อง build ใหม่

### ชนิดตารางที่รองรับ

| `kind` | ใช้ทำอะไร | ตัวอย่าง |
|---|---|---|
| `quality` | จำนวนที่ตรวจ / ผ่านเกณฑ์ / ร้อยละ + สาเหตุที่ไม่ผ่าน | ตารางที่ 1 |
| `count_pct` | นับจำนวนคนที่เข้าเงื่อนไข + ร้อยละของฐาน | 6-12y ตาราง 2, 4, 6 |
| `mean` | ค่าเฉลี่ยต่อคน (ผลรวม ÷ จำนวนคนในฐาน) | 6-12y ตาราง 3, 5 |

### แถวของตาราง (`rows`)

| ค่า | ผลลัพธ์ |
|---|---|
| `age` | แยกแถวรายปี (6, 7, 8, …) — ใช้ในกลุ่ม 6-12 ปี |
| `bands` | แยกแถวเป็นช่วงอายุตามที่นิยามใน `bands:` — ใช้ในกลุ่ม 0-5 ปี (0-2, 3-5) |

```yaml
bands:
  - {label: "0-2", min: 0, max: 2}
  - {label: "3-5", min: 3, max: 5}
```

### เกณฑ์คุณภาพที่ต่างกันตามช่วงอายุ

`quality_filter` ใช้กับทุกแถว ส่วน `quality_extra` เพิ่มเงื่อนไขเฉพาะบางช่วง:

```yaml
quality_filter: "providertype in ['02','06'] and dteeth >= 1 and dteeth <= 20"
quality_extra:
  "0-2": "dteeth + dextract == 20"     # ใช้กับช่วง 0-2 เท่านั้น
```

ในตารางที่ 1 ถ้าอยากให้คอลัมน์ "ไม่ผ่านเกณฑ์" ข้อไหนนับเฉพาะบางช่วง ให้ใส่ `bands:` ในข้อนั้น

### ตัวชี้วัดของแถบสรุปรายอำเภอ

กลุ่ม 0-5 ปีนับฟันน้ำนม กลุ่ม 6-12 ปีนับฟันแท้ — กำหนดใน `overview:`

```yaml
overview:
  caries_free: "dcaries + dfilling + dextract == 0"
  dmft: "dcaries + dfilling + dextract"
  caries_free_label: "ปราศจากฟันผุ (ฟันน้ำนม)"
  dmft_label: "dmft เฉลี่ย"
```

## สำหรับผู้พัฒนา

### รันแบบ dev

ง่ายสุด: **ดับเบิลคลิก `run.bat`** (ติดตั้ง dependencies ให้อัตโนมัติในครั้งแรก)

หรือสั่งเอง — ต้อง `cd` เข้าโฟลเดอร์ `DentalDX` ก่อน:

```powershell
cd C:\Users\ident\cowork\dataexchange\DentalDX
py -m pip install -r requirements.txt
py app.py
```

> ถ้าพิมพ์ `python` แล้ว Windows เด้งหน้าต่าง "Select an app to open" ให้ใช้ `py` แทน
> (เกิดจาก App Execution Alias ของ Microsoft Store — ปิดได้ที่
> Settings → Apps → Advanced app settings → App execution aliases → ปิด python.exe / python3.exe)

ตั้งค่าผ่าน environment variable ได้:
`DENTALDX_DATA`, `DENTALDX_PROFILES`, `DENTALDX_REF`, `DENTALDX_PORT`, `DENTALDX_NO_BROWSER=1`

### build เป็น exe

**วิธีที่แนะนำ — ให้ GitHub Actions build ให้** (ไม่ต้องมีเครื่อง Windows)

```bash
# แก้เลขเวอร์ชันใน app.py ก่อน (ตัวแปร VERSION)
git tag v2.0.0
git push origin v2.0.0
```

Workflow `.github/workflows/build-windows.yml` จะ:

1. รัน `tools/smoke_test.py` ตรวจว่า engine ยังคำนวณถูก (ใช้ข้อมูลจำลอง)
2. build exe ด้วย PyInstaller บน `windows-latest`
3. แพ็กเป็น `DentalDX-vX.Y.Z-win64.zip` (exe + profiles + reference + โฟลเดอร์ data เปล่า)
4. สร้าง GitHub Release พร้อมแนบไฟล์ให้ดาวน์โหลด

กดสั่ง build เองได้ที่แท็บ **Actions → Build Windows EXE → Run workflow**
(ไม่สร้าง Release แต่ได้ไฟล์ใน Artifacts)

**build เองบนเครื่อง Windows**

```
build.bat
```

ได้ผลลัพธ์ที่ `dist\DentalDX\` — **ส่งทั้งโฟลเดอร์** ไม่ใช่แค่ไฟล์ .exe
(เพราะ `profiles/`, `reference/`, `data/` ตั้งใจให้อยู่นอก exe)

### ทดสอบ

```bash
python tools/smoke_test.py
```

สร้างข้อมูลจำลอง → รันทุก profile → ตรวจว่าทุกตารางคำนวณได้ มี insight และส่งออก xlsx ได้

## ⚠️ ความเป็นส่วนตัวของข้อมูล

ไฟล์ข้อมูลจาก HDC มีเลขบัตรประชาชน ชื่อ และที่อยู่ **ห้าม commit ขึ้น GitHub เด็ดขาด**

`.gitignore` กันไว้ให้แล้ว (`data/**`, `*.xlsx`, `*.csv` ยกเว้นไฟล์ใน `reference/`)
ก่อน push ทุกครั้งควรเช็ค:

```bash
git status --short          # ต้องไม่มีไฟล์ .xlsx ของผู้ป่วยโผล่มา
git ls-files | grep -i xlsx # ต้องไม่คืนอะไรเลย
```

หากเผลอ commit ไปแล้ว การลบไฟล์ใน commit ใหม่ **ไม่พอ** — ต้องล้างประวัติด้วย
`git filter-repo` หรือ BFG Repo-Cleaner และถือว่าข้อมูลนั้นรั่วแล้ว

### โครงสร้างโค้ด

```
app.py              Flask routes + จุดเริ่มโปรแกรม
core/loader.py      อ่าน xlsx/csv, normalize คอลัมน์, จัดการค่า <NA>, join hospitals
core/derive.py      คำนวณ age, examined, gum_status, gum_sextant, dmft
core/engine.py      แปลง spec จาก YAML → ตารางรายงาน (ใช้ร่วมทุกกลุ่มอายุ)
core/profiles.py    ค้นหา/โหลด profile จากโฟลเดอร์ profiles/
core/service.py     cache + กรองพื้นที่ + ประกอบรายงาน
templates/          หน้าเว็บ (ไม่มี dependency ภายนอก ทำงานแบบ offline ได้)
```

**หลักการ**: `core/` ไม่รู้จักกลุ่มอายุใด ๆ เลย ความรู้เฉพาะกลุ่มอยู่ใน `profiles/*.yaml` ทั้งหมด

## ข้อควรทราบเรื่องข้อมูล

| เรื่อง | รายละเอียด |
|---|---|
| แถวที่ถือว่าตรวจฟัน | `date_serv` ไม่เป็นค่าว่าง |
| เด็กในเขตรับผิดชอบ (เป้าหมาย) | ทุกแถวในไฟล์ รวมแถวที่ยังไม่ได้ตรวจ |
| ร้อยละได้รับการตรวจฟัน | จำนวนที่ตรวจ ÷ ทุกแถวในไฟล์ (ของพื้นที่นั้น) |
| อายุ | คำนวณจาก `date_serv − birth` (ปัดลงเป็นปีเต็ม) |
| ค่าว่างในไฟล์ | HDC ส่งมาเป็นข้อความ `<NA>` ไม่ใช่ช่องว่างจริง — โปรแกรมแปลงให้อัตโนมัติ |
| `hospitals.csv` | เข้ารหัส TIS-620/CP874 ไม่ใช่ UTF-8 — โปรแกรมตรวจจับให้อัตโนมัติ |
| `GUM` | 6 หลัก (sextant) ถ้าไม่ครบ 6 หลักถือว่าตรวจไม่ได้ (999999) |
| ชื่ออำเภอ | ตัดรหัสนำหน้าออกให้ เช่น `01-เมืองชัยภูมิ` → `เมืองชัยภูมิ` |
