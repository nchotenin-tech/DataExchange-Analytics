### รันแบบ dev

ง่ายสุด: **ดับเบิลคลิก `run.bat`** (ติดตั้ง dependencies ให้อัตโนมัติในครั้งแรก)

หรือสั่งเอง — ต้อง `cd` เข้าโฟลเดอร์ `DentalDX` ก่อน:

```powershell
cd C:\Users\ident\cowork\dataexchange\DentalDX
py -m pip install -r requirements.txt
py app.py
```

> ถ้าพิมพ์ `python` แล้ว Windows เด้งหน้าต่าง "Select an app to open" ให้ใช้ `py` แทน
> (เกิดจาก App Execution Alias ของ Microsoft Store — ปิดได้ที่
> Settings → Apps → Advanced app settings → App execution aliases → ปิด python.exe / python3.exe)

ตั้งค่าผ่าน environment variable ได้:
`DENTALDX_DATA`, `DENTALDX_PROFILES`, `DENTALDX_REF`, `DENTALDX_PORT`, `DENTALDX_NO_BROWSER=1`

### build เป็น exe

**วิธีที่แนะนำ — ให้ GitHub Actions build ให้** (ไม่ต้องมีเครื่อง Windows)

```bash
# แก้เลขเวอร์ชันใน app.py ก่อน (ตัวแปร VERSION)
git tag v2.0.0
git push origin v2.0.0
```

Workflow `.github/workflows/build-windows.yml` จะ:

1. รัน `tools/smoke_test.py` ตรวจว่า engine ยังคำนวณถูก (ใช้ข้อมูลจำลอง)
2. build exe ด้วย PyInstaller บน `windows-latest`
3. แพ็กเป็น `DentalDX-vX.Y.Z-win64.zip` (exe + profiles + reference + โฟลเดอร์ data เปล่า)
4. สร้าง GitHub Release พร้อมแนบไฟล์ให้ดาวน์โหลด

กดสั่ง build เองได้ที่แท็บ **Actions → Build Windows EXE → Run workflow**
(ไม่สร้าง Release แต่ได้ไฟล์ใน Artifacts)

**build เองบนเครื่อง Windows**

```
build.bat
```

ได้ผลลัพธ์ที่ `dist\DentalDX\` — **ส่งทั้งโฟลเดอร์** ไม่ใช่แค่ไฟล์ .exe
(เพราะ `profiles/`, `reference/`, `data/` ตั้งใจให้อยู่นอก exe)

### ทดสอบ

```bash
python tools/smoke_test.py
```

สร้างข้อมูลจำลอง → รันทุก profile → ตรวจว่าทุกตารางคำนวณได้ มี insight และส่งออก xlsx ได้

## ⚠️ ความเป็นส่วนตัวของข้อมูล

ไฟล์ข้อมูลจาก HDC มีเลขบัตรประชาชน ชื่อ และที่อยู่ **ห้าม commit ขึ้น GitHub เด็ดขาด**

`.gitignore` กันไว้ให้แล้ว (`data/**`, `*.xlsx`, `*.csv` ยกเว้นไฟล์ใน `reference/`)
ก่อน push ทุกครั้งควรเช็ค:

```bash
git status --short          # ต้องไม่มีไฟล์ .xlsx ของผู้ป่วยโผล่มา
git ls-files | grep -i xlsx # ต้องไม่คืนอะไรเลย
```

หากเผลอ commit ไปแล้ว การลบไฟล์ใน commit ใหม่ **ไม่พอ** — ต้องล้างประวัติด้วย
`git filter-repo` หรือ BFG Repo-Cleaner และถือว่าข้อมูลนั้นรั่วแล้ว

### โครงสร้างโค้ด

```
app.py              Flask routes + จุดเริ่มโปรแกรม
core/loader.py      อ่าน xlsx/csv, normalize คอลัมน์, จัดการค่า <NA>, join hospitals
core/derive.py      คำนวณ age, examined, gum_status, gum_sextant, dmft
core/engine.py      แปลง spec จาก YAML → ตารางรายงาน (ใช้ร่วมทุกกลุ่มอายุ)
core/profiles.py    ค้นหา/โหลด profile จากโฟลเดอร์ profiles/
core/service.py     cache + กรองพื้นที่ + ประกอบรายงาน
templates/          หน้าเว็บ (ไม่มี dependency ภายนอก ทำงานแบบ offline ได้)
```

**หลักการ**: `core/` ไม่รู้จักกลุ่มอายุใด ๆ เลย ความรู้เฉพาะกลุ่มอยู่ใน `profiles/*.yaml` ทั้งหมด

## ข้อควรทราบเรื่องข้อมูล

| เรื่อง | รายละเอียด |
|---|---|
| แถวที่ถือว่าตรวจฟัน | `date_serv` ไม่เป็นค่าว่าง |
| เด็กในเขตรับผิดชอบ (เป้าหมาย) | ทุกแถวในไฟล์ รวมแถวที่ยังไม่ได้ตรวจ |
| ร้อยละได้รับการตรวจฟัน | จำนวนที่ตรวจ ÷ ทุกแถวในไฟล์ (ของพื้นที่นั้น) |
| อายุ | คำนวณจาก `date_serv − birth` (ปัดลงเป็นปีเต็ม) |
| ค่าว่างในไฟล์ | HDC ส่งมาเป็นข้อความ `<NA>` ไม่ใช่ช่องว่างจริง — โปรแกรมแปลงให้อัตโนมัติ |
| `hospitals.csv` | เข้ารหัส TIS-620/CP874 ไม่ใช่ UTF-8 — โปรแกรมตรวจจับให้อัตโนมัติ |
| `GUM` | 6 หลัก (sextant) ถ้าไม่ครบ 6 หลักถือว่าตรวจไม่ได้ (999999) |
| ชื่ออำเภอ | ตัดรหัสนำหน้าออกให้ เช่น `01-เมืองชัยภูมิ` → `เมืองชัยภูมิ` |
